# The three closing responsibilities

## 1. Know when to delegate

Delegation defines which work Claude may assist with, what must remain human-controlled, and what should not be delegated.

```text
Claude can assist
      ≠
Claude should own the decision
```

## 2. Know when to validate

Validation is required whenever an output may influence a meaningful decision, external communication, calculation, workflow action, or consequential result.

```text
Plausible output
      ≠
Verified output
```

## 3. Know when to escalate

Escalation is appropriate when the task exceeds the user's authority, expertise, approved environment, or the Associate-level workflow boundary.

```text
Able to identify the issue
      ≠
Authorized or qualified to resolve it alone
```

# Associate operating card

```text
1. What outcome is required?
2. Which evidence and constraints control the task?
3. Which product, model, feature, or tool fits?
4. What must Claude do, and what remains human-owned?
5. How will the result be validated?
6. What should persist, and in which configuration layer?
7. Is the use approved, proportionate, fair, and accountable?
8. If performance is weak, where is the failure located?
9. What is the smallest validated repair?
10. Does the issue require escalation?
```

- review decision frameworks rather than memorizing prose;

- avoid using remembered or reconstructed live-exam questions.
