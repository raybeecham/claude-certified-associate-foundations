# Capabilities now developed

## 1. Configuration leverage

```text
Using Claude
      ≠
Operating a configured Claude environment
```

A configured baseline preserves recurring behavior, approved sources, reusable procedures, continuity, access boundaries, tests, and maintenance responsibilities across conversations.

## 2. Mechanism selection

| Need | Primary home |
|---|---|
| Immediate task | Current request |
| Project behavior | Project instructions |
| Project facts and references | Project knowledge |
| Reusable procedure | Skill |
| Selected continuity | Project-scoped Memory |
| External source access | Connector |
| Exact rule or authorization | Deterministic control |
| Approved durable state | System of record |

## 3. Bounded Projects and continuity

```text
Project-scoped continuity
      ≠
Authorization boundary
      ≠
Confidentiality control
      ≠
System of record
```

Project separation supports contextual scope but does not replace identity, permissions, records, or data-handling controls.

## 4. Connector and knowledge governance

The learner can maintain capability and source contracts covering identity, scope, read and write tools, unsupported actions, approval boundaries, authority, version, freshness, conflicts, owner, review date, and revocation.

```text
Connected or uploaded
      ≠
Authoritative
      ≠
Current
      ≠
Approved for external action
```

## 5. Persistent instruction precision

A durable instruction defines:

- trigger;
- required behavior;
- evidence boundary;
- failure behavior; and
- observable output.

```text
Vague intention
      ≠
Operational behavior
```

Natural-language instructions must be paired with enforceable controls when stakes require them.

## 6. Configuration maintenance

```text
Inventory
  ↓
Review on cadence and after material events
  ↓
Classify drift
  ↓
Edit / replace / disable / revoke / reset / roll back / retire
  ↓
Regression-test
  ↓
Approve, release, and monitor
```

Silent quality degradation often requires inspection of the reusable baseline rather than a stronger model or more elaborate one-time prompt.

```text
Configured workspace
      ↓
```

# Short recap

```text
1. Configuration creates leverage across repeated conversations.
2. Put each concern in the correct mechanism.
3. Give every responsibility one authoritative home.
4. Bound Projects by purpose, users, sources, and disclosure needs.
5. Treat connector access as a capability contract, not blanket authority.
6. Curate knowledge by authority, freshness, scope, and version.
7. Make persistent instructions precise and observable.
8. Pair consequential guidance with enforceable controls.
9. Maintain instructions, knowledge, Skills, connectors, and Memory on cadence.
10. Repair the reusable baseline instead of hiding drift with one-time prompts.
```
