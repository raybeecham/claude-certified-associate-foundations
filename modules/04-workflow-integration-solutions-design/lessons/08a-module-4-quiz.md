# What the quiz measures

The quiz asks which workflow property remains unresolved and which intervention actually addresses it.

```text
Read the scenario
      ↓
Identify the controlling uncertainty, dependency, or authority boundary
      ↓
Select the smallest responsible intervention
      ↓
Reject answers based only on stronger models, confident prose, or hidden automation
```

# Five-domain assessment map

| Domain | Diagnostic question | Strong response |
|---|---|---|
| Requirements | Could two implementers build materially different things? | Quantify or clarify the ambiguous term |
| Verified planning | Does the recommendation depend on exact figures? | Compute with code, then synthesize |
| Escalation boundary | Has a personal helper become shared operational infrastructure? | Escalate toward production engineering and architecture |
| Delegation | Does the step carry authority or irreversible consequence? | Retain qualified human approval |
| Stakeholder communication | Does the message state bounded capability and oversight? | Communicate value and limits together |

# Original five-question quiz

## Question 1: Ambiguous performance requirement

A workflow requirement states: `The service must support heavy usage during peak periods.`

What is the best next step?

A. Accept it because the intent is clear.  
B. Ask for measurable concurrency, transaction volume, response-time, and duration targets.  
C. Choose a more capable model to interpret the phrase.  
D. Build for the highest possible scale.

**Best answer: B**

`Heavy usage` is not testable. Different engineers could reasonably design for radically different loads.

---

## Question 2: Planning figures

A staffing recommendation depends on historical workload growth and resolved cases per analyst.

Which workflow is strongest?

A. Ask Claude to estimate both figures in prose.  
B. Compute the figures over the approved dataset, review and reconcile them, then ask Claude to synthesize scenarios and trade-offs.  
C. Replace the internal dataset with public industry averages.  
D. Ask the model to recall typical values.

**Best answer: B**

The figures must be established deterministically before they are used in a recommendation.

---

## Question 3: Helper becomes infrastructure

A dashboard artifact created for one analyst is now used daily by multiple departments for official reporting.

What does this change?

A. Nothing; continue casual prompt iteration.  
B. The artifact has become a depended-on system and needs production engineering, security, support, ownership, and architecture review.  
C. Only the model tier should change.  
D. The artifact should be moved to a private chat and left unchanged.

**Best answer: B**

Shared operational dependency is an escalation signal. A useful prototype can outgrow Associate-level workflow configuration.

---

## Question 4: Contract authority

Which contract-review stage must remain human-controlled?

A. Extracting candidate clauses.  
B. Drafting proposed redlines.  
C. Approving changes and authorizing signature or transmission.  
D. Computing a penalty amount from explicit terms.

**Best answer: C**

Approval and signing carry professional accountability and irreversible legal consequence.

---

## Question 5: Credible stakeholder description

Which statement best describes an AI-assisted contract workflow?

A. `The AI handles contract review automatically.`  
B. `Claude extracts clauses, flags playbook departures, and drafts proposed redlines; a qualified legal reviewer approves every change before any contract is sent.`  
C. `The AI now performs the legal work.`  
D. `The process is autonomous and no longer requires legal review.`

**Best answer: B**

The statement names the bounded AI work and the retained human authority.

# Reasoning patterns

## Ambiguity test

```text
Could two competent implementers build different solutions?
      ↓
Yes → requirement needs clarification or quantification
```

## Quantitative trust chain

```text
Approved data
      ↓
Defined business rules
      ↓
Code-executed calculation
      ↓
Review and reconciliation
      ↓
Scenario synthesis
      ↓
Human decision
```

## Escalation boundary

```text
Personal helper
      ↓
Repeated team dependency
      ↓
Operational system
      ↓
Engineering, architecture, security, support, and governance review
```

## Delegation boundary

```text
Preparation and drafting → AI or collaborative
Exact calculation        → code or deterministic logic
Approval and commitment  → human-retained
External side effect     → controlled execution after approval
```

## Communication boundary

```text
Capability
+ exclusion
+ observed value
+ limitation
+ human control
= credible description
```

---

# Common distractors

- **Use a stronger model:** does not resolve ambiguous requirements or authority boundaries.
- **Trust polished prose:** does not establish exact calculations.
- **Continue prototype iteration indefinitely:** ignores operational dependency.
- **Collapse drafting into approval:** confuses output quality with authority.
- **Describe the process as automated:** hides retained human work and limitations.

---

# Exam shortcut

```text
Unquantified requirement      → clarify and make testable
Plan depends on exact figures → code execution + reconciliation
Helper becomes depended on    → escalate toward production engineering
Approval or signature         → human-retained
Stakeholder trust             → bounded task + value + limits + human gate
```

---

# Short recap

1. Ambiguous requirements cannot drive reliable design.
2. Material figures must be computed rather than generated.
3. Shared dependency changes a prototype into infrastructure.
4. Authority and irreversible action remain human-controlled.
5. Credibility requires value and limitations in the same description.
