# What Module 3 established

Module 3 converted output review from a subjective impression into a repeatable release workflow.

```text
Define intended use
      ↓
Evaluate requirements, accuracy, and completeness
      ↓
Detect hallucinations, inconsistencies, bias, and omissions
      ↓
Ground material claims in evidence
      ↓
Validate calculations and external actions
      ↓
Apply human-review thresholds
      ↓
Adapt for the audience
      ↓
Select the format and computation method
      ↓
Release, edit, verify, escalate, or reject
```

The module's central principle is:

> Fluency is not proof, and a polished draft is not automatically a releasable deliverable.

# Capabilities now developed

## 1. Discernment

The learner can evaluate output against:

```text
Requirements
    +
Source material
    +
Professional standards
```

This includes separate reviews for accuracy and completeness.

## 2. Failure-pattern recognition

The learner can recognize:

- precise unsupported claims;
- certainty that exceeds evidence;
- internal contradictions;
- confirmation and framing bias;
- missing sources or decision-critical information; and
- unverified claims that an external action occurred.

## 3. Grounding and fact-checking

The learner can:

- permit `unknown` and `not covered` outcomes;
- define a closed or open evidence boundary;
- require auditable citations;
- extract evidence before analysis;
- classify support as supported, qualified, unsupported, conflicting, or not covered; and
- validate consequential claims against authoritative sources.

## 4. Diligence and human review

The learner can apply four thresholds:

```text
Stakes
Reversibility
Audience
Regulatory, contractual, policy, or professional exposure
```

The learner also understands that meaningful human review requires expertise, authority, context, evidence access, time, and intervention rights.

## 5. Audience adaptation

The learner can preserve verified facts, uncertainty, risks, dependencies, and obligations while adapting:

- selection;
- depth;
- tone;
- order;
- vocabulary; and
- format.

## 6. Format and computation selection

The learner can distinguish:

```text
Inline, artifact, and structured output → delivery choices
Code execution                          → computation method
```

Material calculations should be executed, inspected, reconciled, and reviewed rather than generated as plausible prose.

## 7. Release triage

The learner can conclude with an explicit disposition:

```text
Release
Edit
Verify
Escalate
Reject
```

# Transition to Module 4

Module 3 asked:

```text
Is this output trustworthy and releasable?
```

Module 4 asks:

```text
How should the surrounding workflow be designed so the model,
tools, deterministic logic, storage, and people each perform
the responsibilities they are best suited to handle?
```

The transition is:

```text
Verified output discipline
          ↓
Component responsibility boundaries
          ↓
Tool contracts and controlled side effects
          ↓
State, retries, failure handling, and observability
          ↓
Safe workflow integration
```

Module 4 will extend the evaluation discipline by placing it inside an end-to-end workflow rather than treating each output as an isolated response.

# Short recap

```text
1. You own what you release.
2. Evaluate against requirements, sources, and standards.
3. Review accuracy and completeness separately.
4. Treat plausible language as unverified.
5. Build evidence and uncertainty behavior into the prompt.
6. Set human-review thresholds before release pressure appears.
7. Adapt presentation without changing facts or caveats.
8. Use executed computation for material numeric work.
9. Preserve evidence, reproducibility, and approval records.
10. End with an explicit release disposition.
```

> Claude becomes a more useful collaborator when the surrounding human and technical workflow makes unsupported trust difficult.
