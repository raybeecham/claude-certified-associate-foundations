# Module 3 Introduction Prompt Notebook

Use these prompts to practice the accountability, Discernment, Diligence, and release-decision concepts introduced in Module 3.

The prompts are generic study tools. Replace placeholders with fictional, synthetic, public, or explicitly authorized material.

## 1. Accountability-asymmetry analysis

```text
Analyze the following AI-assisted workflow for accountability asymmetry.

Workflow:
[DESCRIBE THE WORKFLOW]

Identify:
1. the immediate and visible benefit;
2. the delayed or hidden cost of an undetected error;
3. who receives the benefit;
4. who bears the risk;
5. the point at which verification should occur; and
6. one control that would reduce the asymmetry.

Return a six-row table followed by a one-paragraph conclusion.
```

## 2. Verification-debt diagnostic

```text
Evaluate whether the following workflow is accumulating verification debt.

Workflow description:
[WORKFLOW]

Available review capacity:
[REVIEWERS, TIME, TOOLS, AND EXPERTISE]

Output volume:
[NUMBER AND FREQUENCY OF OUTPUTS]

Assess:
- unresolved factual claims;
- traceability gaps;
- review backlog;
- inherited assumptions;
- downstream reuse of unverified material;
- cost of correction after release; and
- warning indicators.

Classify the verification-debt level as Low, Moderate, High, or Critical. Explain the evidence and propose the three highest-value controls.
```

## 3. Discernment review

```text
Apply Product, Process, and Performance Discernment to the AI-assisted output below.

Task requirement:
[REQUIREMENT]

Authorized evidence:
[EVIDENCE]

Output:
[OUTPUT]

Review:
1. Product — Does the output meet the quality and completeness requirements?
2. Process — Was the apparent approach appropriate and adequately evidenced?
3. Performance — Did the AI behave appropriately around uncertainty, scope, and limitations?

For every concern, cite the relevant passage or requirement. End with Release, Edit, Verify, Escalate, or Reject.
```

## 4. Diligence statement builder

```text
Draft a diligence statement for the following AI-assisted work product.

Use case:
[USE CASE]

Audience:
[AUDIENCE]

Potential consequences of error:
[CONSEQUENCES]

AI contribution:
[HOW AI WAS USED]

Human review performed:
[REVIEW]

The statement should cover:
- why AI was appropriate for the task;
- how evidence and calculations were verified;
- what limitations remain;
- whether disclosure is required;
- who approved release; and
- what the user should not infer from the output.

Keep the statement factual and proportionate. Do not claim verification that was not performed.
```

## 5. Review-ladder selector

```text
Select the appropriate review level for each output below.

Levels:
1. Surface review
2. Requirement review
3. Evidence review
4. Independent validation
5. Qualified human review

Outputs:
[LIST OUTPUTS]

For each output, state:
- recommended minimum level;
- consequence of error;
- evidence needed;
- reviewer qualifications;
- whether release can proceed if verification is incomplete; and
- escalation trigger.

Return a table ordered from lowest to highest consequence.
```

## 6. Claim inventory

```text
Create a claim inventory for the following draft.

Draft:
[DRAFT]

For each material claim, identify:
- exact claim;
- claim type: fact, calculation, inference, prediction, recommendation, or opinion;
- source supplied;
- support status: supported, partially supported, unsupported, conflicting, or not applicable;
- consequence if wrong;
- verification method; and
- required disposition.

Do not verify from memory. Use only the supplied evidence unless current-source retrieval is explicitly authorized.
```

## 7. Release-disposition exercise

```text

[EVIDENCE]

Output:
[OUTPUT]

Review criteria:
[CRITERIA]

State:
1. the selected disposition;
2. the dominant reason;
3. material defects or uncertainties;
4. the smallest action required before the next decision; and
5. who has authority to approve release.
```

## 8. Consequence-of-error matrix

```text
Build a consequence-of-error matrix for the following AI use case.

Use case:
[USE CASE]

Assess potential errors across:
- factual accuracy;
- omission;
- calculation;
- source attribution;
- biased framing;
- audience misunderstanding;
- privacy or confidentiality;
- policy or regulatory impact; and
- unsafe action.

For each category, rate likelihood and impact as Low, Medium, or High. Recommend a review control and identify whether qualified human review is mandatory.
```

## 9. Cautionary-case reconstruction

```text
Create an original fictional cautionary case showing how one plausible AI-generated error causes delayed professional harm.

Requirements:
- use no real client, employer, or confidential detail;
- make most of the output correct;
- include one subtle unsupported claim;
- show why the claim passed superficial review;
- show the delayed consequence;
- identify the missing Discernment practice;
- identify the missing Diligence practice; and
- conclude with a concrete workflow control.

Keep the case under 450 words.
```

## 10. Evaluation-contract builder

```text
Convert the following task specification into an evaluation contract.

Task specification:
[TASK SPECIFICATION]

Define:
- intended purpose;
- material quality dimensions;
- measurable acceptance criteria;
- evidence or test for each criterion;
- reviewer or grader;
- release-blocking failures;
- uncertainty behavior;
- approval authority; and
- final dispositions.

Return the result as a structured table.
```

## 11. Ceremonial-review detector

```text
Assess whether the human review step in this workflow is meaningful or ceremonial.

Workflow:
[WORKFLOW]

Reviewer:
[ROLE AND EXPERTISE]

Time available:
[TIME]

Evidence available:
[EVIDENCE]

Authority:
[AUTHORITY]

Evaluate whether the reviewer has:
- relevant expertise;
- sufficient context;
- access to source evidence;
- time to inspect material claims;
- authority to reject or escalate;
- independence from production pressure; and
- a defined review checklist.

Return Meaningful, Partially Meaningful, or Ceremonial, with corrective actions.
```

## 12. Discernment-versus-Diligence classifier

```text
Classify each action below as primarily Discernment, Diligence, Both, or Neither.

Actions:
[ACTIONS]

For each classification, explain:
- whether it evaluates quality or behavior;
- whether it addresses responsibility, transparency, verification, or deployment;
- what is missing; and
- one stronger version of the action.
```

## 13. Educational-notice adaptation

```text
Draft a concise educational-use notice for the following public study resource.

Resource:
[RESOURCE DESCRIPTION]

The notice should state that:
- the material is educational;
- examples may be fictional or illustrative;
- it is not professional advice;
- product behavior and policies may change;
- current official documentation controls when conflicts exist; and
- users remain responsible for adapting the material to their situation.

Avoid legalistic overstatement. Keep it under 140 words.
```

## 14. Module 2-to-Module 3 bridge drill
