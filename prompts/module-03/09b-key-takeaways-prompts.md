# Module 3 Notebook: Key Takeaways

Use these prompts to review and apply the six durable lessons from Module 3.

---

## 1. Six-takeaway recall drill

```text
Without notes, explain the six Module 3 takeaways:
1. accountability;
2. three evaluation references;
3. plausible versus verified;
4. verification built into prompts;
5. precommitted review thresholds; and
6. format by reliability.

For each, give one practical example and one failure prevented.
```

---

## 2. Accountability map

```text
Map accountability for this AI-assisted workflow.

Identify who owns:
- task definition;
- evidence authorization;
- validation;
- professional review;
- release approval;
- external action;
- monitoring; and
- correction.

Flag any stage where accountability is incorrectly assigned to the model or left unowned.
```

---

## 3. Three-reference evaluation

```text
Evaluate this output against:
1. requirements;
2. source material; and
3. professional standards.

Then review accuracy and completeness separately.

Return:
- findings by reference;
- missing or unsupported elements;
- stakes-calibrated review depth; and
- release, edit, verify, escalate, or reject.
```

---

## 4. Plausibility-signature scan

```text
Scan this output for high-risk signatures:
- precise claims without sources;
- confidence that exceeds evidence;
- repeated facts that disagree;
- framing that mirrors a preferred answer;
- missing sources or conditions;
- claimed external actions without proof.

For each signature, state the targeted verification required.
```

---

## 5. Verification-by-design prompt

```text
Rewrite this task prompt so the output is easier to verify.

Include:
- explicit evidence boundary;
- permission to answer unknown or not covered;
- precise source-location requirements;
- quote-first analysis where appropriate;
- support-status labels;
- required independent checks; and
- release blockers.
```

---

## 6. Citation-support audit

```text
For every material claim in this draft:
- identify the citation;
- open or locate the cited passage;
- determine whether it supports the full claim;
- preserve scope, date, conditions, and exceptions;
- classify Supported, Qualified, Unsupported, Conflicting, or Not Covered; and
- recommend Keep, Revise, Remove, Verify, or Escalate.
```

---

## 7. Diligence-threshold review

```text
Assess this output using:
- stakes;
- reversibility;
- audience; and
- regulatory, contractual, policy, or professional exposure.

Identify any automatic do-not-ship gate and define the reviewer expertise, authority, evidence, time, and intervention rights required.
```

---

## 8. Iteration-versus-escalation test

```text
Determine whether this task should receive another prompt revision or be escalated.

Classify the remaining blocker as:
- prompt;
- evidence;
- tool;
- authority; or
- professional judgment.

Use the improvement history and stakes to recommend:
- targeted iteration;
- obtain evidence;
- repair the workflow;
- qualified human review; or
- reject the output.
```

---

## 9. Format-and-reliability selector

```text
Select the appropriate output package for this task.

Evaluate:
- immediate versus standalone use;
- human versus machine consumer;
- editability and reuse;
- schema needs;
- calculations and precision;
- charts or processed files;
- provenance;
- review and approval; and
- sensitivity.

Choose the minimum necessary combination of inline, artifact/file, structured output, and code execution.
```

## 10. Numeric trust-chain builder

Design a trustworthy workflow for this material calculation.

4. execution;
5. row-count and control-total reconciliation;

## 11. Integrated release review

```text
Review this AI-assisted deliverable end to end.

Determine whether it is:
- correct enough;
- complete enough;
- supported enough;
- reviewed enough;
- appropriate enough for its audience;
- delivered in the correct format; and
- reproducible enough for the intended use.

Return a release decision with the controlling reason and next action.
```
