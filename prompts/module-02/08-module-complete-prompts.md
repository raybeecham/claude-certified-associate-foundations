# Module 2 Completion and Transition Prompts

Use these prompts to consolidate Prompting and Task Execution before moving to Module 3.

The prompts are study aids, not universal production templates. Replace bracketed fields with fictional, public, synthetic, or authorized information.

## 1. Sixty-second Module 2 summary

```text
Give a spoken, sixty-second summary of Module 2 using these five ideas:

1. functional prompt structure;
2. minimum sufficient context;
3. sequential and parallel decomposition;
4. targeted diagnostic iteration; and
5. task-type strategy.

Include one sentence explaining why deterministic calculation belongs outside prose generation.
After the summary, identify anything inaccurate, vague, or missing.
```

## 2. Component-stack recall drill

```text
Ask me to reconstruct the course component stack from memory.

After I answer:
- identify missing or misplaced components;
- distinguish optional Role from required task information;
- ask me what each component contributes; and
- give me one weak prompt to repair.

Do not reveal the answer before I attempt it.
```

## 3. Context-gap detector

```text
Present five short prompts that are likely to produce generic output because important context remains implicit.

For each prompt, ask me:
1. what the author probably knows but did not state;
2. which context is necessary;
3. which details would be irrelevant; and
4. what the minimum sufficient context would be.

Use fictional professional scenarios.
```

## 4. Decomposition oral board

```text
Give me a complex professional request containing at least four dependent tasks and two possible parallel branches.

Ask me to:
- identify the shared foundation;
- define ordered stages;
- specify Input, Process, Output, and Validation for each stage;
- identify the fan-out point;
- define the fan-in consistency review; and
- explain why an alternative ordering is weaker.

Score my answer for dependency logic, inspectability, and validation.
```

## 5. Diagnostic-iteration drill

```text
Provide a prompt and a disappointing output.

The output should be mostly correct but fail on one or two dimensions.
Ask me to:
- identify what already works;
- name the dominant failed component;
- make the smallest targeted revision;
- define how to compare the revised output with the prior output; and
- state when to stop iterating.

Do not accept a wholesale rewrite unless the prompt is fundamentally incomplete.
```

## 6. Task-strategy calibration drill

```text
Present eight requests: two analysis, two research, two drafting, and two brainstorming tasks.

For each, ask me to identify:
- the dominant task type;
- what must be tightened;
- what should remain flexible;
- what evidence is required;
- whether current retrieval is necessary;
- whether the task should be decomposed; and
- the main strategy-mismatch risk.

Include at least one deliberately over-constrained brainstorming request.
```

## 7. Repair-the-prompt capstone

```text
Create an original exercise with:
- a weak prompt;
- a plausible but disappointing output;
- the author's actual decision need;
- six possible repair fragments; and
- one polished-sounding distractor.

Ask me to complete three stages:
1. diagnose all material specification gaps;
2. map each useful fragment to Role, Context, Task, Constraints, Output Format, Evidence, Process, or Success Criteria; and
3. assemble the minimum sufficient repaired prompt.

Include one operation that should be routed to code or another deterministic tool.
Reveal the model answer only after my attempt.
```

## 8. Distractor analysis

```text
Create five certification-style questions about Prompting and Task Execution.

For every question:
- include one best answer;
- include three plausible distractors;
- ask me to select the answer;
- require me to explain why the nearest distractor is weaker; and
- identify the dominant concept being tested.

Cover specification, decomposition, iteration, strategy, and deterministic verification.
```

## 9. Evidence of mastery review

```text
Interview me to determine whether I have transferable Module 2 mastery rather than memorized recall.

Use one question at a time and test whether I can:
- repair a vague task;
- supply minimum sufficient context;
- decompose a hybrid workflow;
- preserve a shared validated foundation;
- localize an output failure;
- calibrate analysis versus brainstorming; and
- route exact operations to code.

At the end, return:
- demonstrated strengths;
- unresolved gaps;
- one transfer exercise;
- one recommended review lesson; and
- a readiness judgment for Module 3.
```

## 10. New-workflow transfer test

```text
Help me apply Module 2 to this authorized or synthetic workflow:

[DESCRIBE WORKFLOW]

Work through:
1. business objective;
2. audience and downstream use;
3. authorized evidence;
4. dominant task type;
5. component stack;
6. decomposition and dependencies;
7. deterministic operations;
8. output contract;
9. uncertainty behavior;
10. success criteria;
11. likely failure modes; and
12. human-review responsibility.

Do not write the final prompt until the workflow design is coherent.
```

## 11. Module 2 to Module 3 bridge

```text
Take this prompt specification:

[PASTE PROMPT]

Convert it into an initial evaluation plan for Module 3.

Create:
- measurable success criteria;
- a normal test case;
- an edge case;
- a missing-information case;
- a conflicting-evidence case;
- an adversarial case;
- deterministic checks;
- human-review criteria;
- release-blocking failures; and
- a regression test.

Explain how each evaluation item traces back to the prompt's task contract.
```

## 12. Prompting versus evaluation boundary

```text
Give me ten failure scenarios.

For each, ask me whether the strongest intervention belongs to:
- prompt specification;
- context management;
- model selection;
- evidence retrieval;
- code or deterministic tooling;
- evaluation;
- permissions or governance;
- workflow redesign; or
- human review.

Require a one-sentence justification and identify cases where several layers must change.
```

## 13. Spaced-review flashcard generator

```text
Generate twenty original flashcards for Module 2.

Requirements:
- five component-stack cards;
- four decomposition cards;
- four diagnostic-iteration cards;
- four task-strategy cards;
- three deterministic-verification cards;
- scenario-based questions where possible;
- concise answers; and
- no reproduction of proprietary course or exam wording.
```

## 14. Seven-day retention plan

```text
Create a seven-day Module 2 retention plan.

Constraints:
- fifteen minutes per day;
- active recall before rereading;
- at least two scenario drills;
- one decomposition exercise;
- one repair exercise;
- one timed five-question quiz;
- one transfer task; and
- a final bridge into Module 3 evaluation concepts.

Return a daily table with Activity, Time, Evidence of Completion, and Review Trigger.
```

## 15. Completion reflection

```text
Help me write a private learning reflection for Module 2.

Ask me for:
- the concept that changed my approach most;
- the mistake I am most likely to repeat;
- one workflow where I will apply decomposition;
- one task where I need more creative latitude;
- one operation I should route to code;
- one output that requires human review; and
- one question I am carrying into Module 3.

Return a concise reflection and three commitments.
Do not include employer, client, or sensitive project details unless explicitly authorized.
```

## Public-repository rule

Do not put client names, confidential workflows, proprietary course questions, remembered exam content, credentials, or sensitive performance records into public prompt notebooks. Use fictional, generic, synthetic, public, or explicitly authorized scenarios.
