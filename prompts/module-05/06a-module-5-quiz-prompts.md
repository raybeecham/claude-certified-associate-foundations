# Module 5 Prompt Notebook: Quiz and Remediation

Use fictional, synthetic, public, or explicitly authorized configuration examples. Do not include credentials, private connector identifiers, confidential files, proprietary instructions, or nonpublic Memory exports.

## 1. Mechanism-selection drill

```text
Classify each recurring need as one of:
- current request;
- Project instructions;
- Project knowledge;
- Skill;
- scoped Memory;
- connector;
- deterministic control;
- system of record.

For each answer, state:
- why the mechanism fits;
- why the nearest distractor does not; and
- whether a paired mechanism is also required.

Needs:
[insert fictional needs]
```

## 2. Procedure-versus-instruction audit

```text
Review this Project configuration:
[configuration]

Identify any multi-step procedure buried in Project instructions.
For each finding:
- separate persistent behavior from reusable procedure;
- propose the instruction text that should remain;
- define the Skill candidate;
- identify required knowledge inputs; and
- define a regression test.
```

## 3. Sensitive-workstream separation

```text
Two sensitive workstreams currently share this Project:
[description]

Assess whether they should remain together.
Review:
- business purpose;
- users;
- source sets;
- confidentiality and disclosure boundaries;
- connector identities;
- Project instructions;
- Memory continuity;
- systems of record; and
- offboarding.

Recommend the minimum safe configuration structure.
Do not treat Project separation as a substitute for permissions or data controls.
```

## 4. Connector capability scenario

```text
A workflow expects this connector to perform these stages:
[connector and stages]

Create a capability table for:
- search;
- read;
- attachment retrieval;
- draft;
- create;
- update;
- send or publish;
- delete;
- unsupported action;
- human approval; and
- controlled execution.

Identify any stage the workflow assumes without evidence.
```

## 5. Unsupported-action diagnosis

```text
The connector produced this result:
[result]
The user expected:
[expected action]

Classify the likely issue as:
- installation or enablement;
- authentication;
- permission;
- scope;
- tool loading;
- capability boundary;
- source problem;
- external-system failure; or
- probable product defect.

State the minimum evidence needed before escalation.
```

## 6. Two-reader instruction test

```text
Apply the two-reader test to these standing instructions:
[instructions]

For each instruction:
- identify ambiguous terms;
- define the trigger;
- define required behavior;
- define evidence boundaries;
- define failure behavior;
- define observable output; and
- rewrite it so two competent readers would interpret it consistently.
```

## 7. Meeting-notes instruction repair

```text
Rewrite this vague instruction:
"Write clear and useful meeting notes."

The improved instruction must define:
- decision format;
- action-item format;
- owner and due-date handling;
- missing-owner label;
- unresolved-question section;
- source or transcript boundary; and
- what to do when the source is unclear.
```

## 8. Quiet-drift investigation

```text
A recurring Project produces outdated output even though the current prompt has not changed.
Configuration inventory:
[instructions, knowledge, Skills, connectors, Memory]

Determine:
- which components are current;
- which are stale;
- which conflict;
- which are ownerless;
- the downstream impact;
- the smallest sufficient maintenance action;
- required regression tests; and
- rollback criteria.
```

## 9. Configuration consistency matrix

```text
Create a consistency matrix across:
- Project instructions;
- Project knowledge;
- Skills;
- connector capabilities;
- Memory;
- deterministic controls; and
- systems of record.

Check for:
- year or period mismatches;
- terminology drift;
- duplicate authority;
- stale reviewers;
- unsupported actions;
- source conflicts;
- procedure-version mismatch; and
- outdated continuity.
```

## 10. Distractor analysis

```text
For this Module 5-style scenario:
[scenario and choices]

For each option:
- identify the assumption it makes;
- state whether it addresses the controlling problem;
- identify any hidden risk; and
- explain why the best answer is the smallest responsible intervention.
```

## 12. Oral certification drill

```text
Give me one Module 5 scenario at a time.
After I answer, grade me on whether I:
- selected the correct configuration layer;
- distinguished access from authority;
- respected connector capability boundaries;
- applied the two-reader test;
- recognized configuration drift;
- retained technical and human controls; and
- chose the smallest responsible repair.

Do not reveal the answer before I respond.
```

## 13. End-to-end Project review

```text

[Project description]

- bounded purpose and users;
```

## 14. Five-question recall

```text
Without looking at notes, answer:
1. Where does a repeatable multi-step method belong?
2. How should unrelated sensitive workstreams be configured?
3. What does an unsupported connector action usually indicate?
4. What makes a standing instruction operational?
5. What should be inspected when output drifts without a prompt change?

Then compare my answers with the Module 5 framework and provide targeted remediation.
```
