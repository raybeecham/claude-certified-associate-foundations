# Module 5 Prompt Notebook: System-Level Instructions That Stick

Use fictional, synthetic, public, or explicitly authorized scenarios. Do not place credentials, confidential instructions, private source material, or nonpublic organizational controls in this notebook.

## 1. Identify durable behavior

```text
Review this recurring workflow description:
[workflow]

Separate:
- behavior users repeatedly retype;
- Project-specific facts;
- reusable procedures;
- temporary task details;
- continuity;
- exact rules or authorization controls; and
- secrets or credentials.

Recommend which items belong in Project instructions and which belong elsewhere.
```

## 2. Repair a vague instruction

```text
Rewrite this vague standing instruction as an observable operating rule:
[instruction]

Define:
- trigger;
- required behavior;
- evidence boundary;
- failure behavior;
- observable output; and
- one test case.
```

## 3. Two-reader test

```text
Apply the two-reader test to these instructions:
[instructions]

Identify any phrase that two competent readers could interpret differently.
For each ambiguity, propose a precise replacement.
```

## 4. Evidence guardrail

```text
Draft Project instructions that require:
- citations for material factual claims;
- exact source locations where available;
- explicit handling of unsupported claims;
- visible conflicting evidence;
- no silent gap filling; and
- reviewer escalation for unresolved authority.
```

## 5. Report-format defaults

```text
Create precise Project instructions for recurring reports with:
- a one-sentence headline;
- required section order;
- paragraph or bullet limits;
- acronym treatment;
- figure-source requirements;
- action-item fields; and
- approval-status labeling.
```

## 6. Missing-data behavior

```text
Write standing instructions for these missing-data states:
- source silent;
- source incomplete;
- sources conflict;
- required figure absent;
- unsupported user assumption; and
- unknown approval status.

Use explicit labels and escalation behavior.
```

## 7. Instruction versus Skill

```text
For each recurring requirement below, classify it as:
- Project instruction;
- Project knowledge;
- Skill;
- scoped Memory;
- deterministic control;
- current request; or
- secret-management concern.

Explain the governing distinction.

[requirements]
```

## 8. Conflict register

```text
Two maintained instructions conflict:
[instruction A]
[instruction B]

Create a conflict record with:
- exact conflict;
- scope;
- owner;
- version;
- authority;
- likely supersession;
- interim behavior;
- resolution owner; and
- tests to rerun.
```

## 9. Instruction test suite

```text
Create positive, boundary, adversarial, and regression tests for this instruction set:
[instructions]

Include:
- normal supported case;
- missing evidence;
- conflicting sources;
- user asks to bypass the rule;
- format exception;
- unrelated task;
- draft-versus-approved status; and
- changed instruction behavior.
```

## 10. Security-boundary audit

```text
Review these natural-language restrictions:
[instructions]

Identify which require additional:
- permissions;
- deterministic validation;
- tool restrictions;
- human review;
- approval gates;
- logging; or
- systems of record.

Do not treat instruction text as technical enforcement.
```

## 11. Before-and-after exercise

```text
Convert each vague instruction into a precise one:
- Be professional.
- Be concise.
- Verify facts.
- Make the report accurate.
- Flag risks.
- Do not make mistakes.

For each, provide an observable test.
```

## 12. Instruction overload audit

```text
Review this Project instruction block:
[block]

Identify:
- facts that belong in knowledge;
- procedures that belong in a Skill;
- temporary details;
- continuity items;
- exact controls;
- duplicated rules;
- vague language; and
- rules lacking failure behavior.
```

## 13. Change record

```text
Create a versioned change record for this instruction update:
[old instruction]
[new instruction]

Include reason, owner, affected workflows, risks, tests, approval, effective date, rollback, and next review date.
```

## 14. Oral certification drill

```text
Give me ten short scenarios about persistent instructions.
For each, ask me to identify:
1. whether the need belongs in instructions;
2. what makes the rule testable;
3. what happens when evidence is missing; and
4. what technical or human control remains necessary.

Wait for my answer before revealing the reasoning.
```
