# Module 7 Completion and Transition Prompts

Use these prompts to consolidate troubleshooting and optimization before beginning Module 8.

## 1. Full diagnostic recall

```text
Without consulting notes, explain the Module 7 diagnostic sequence in order.
For each stage, provide:
- the symptom pattern;
- the likely cause;
- the cheapest controlled test; and
- the appropriate first repair.
```

## 2. Symptom-to-cause drill

```text
Create five fictional underperformance scenarios representing:
1. under-specification;
2. context overload;
3. wrong feature or model;
4. stale configuration; and
5. expectation mismatch.
For each, identify the timing evidence, alternate hypothesis, and one-variable test.
```

## 3. Isolation discipline

```text
Given this fictional failing workflow:
[describe workflow]
Create a diagnostic record with:
- expected behavior;
- observed behavior;
- earliest failing stage;
- primary hypothesis;
- alternate hypothesis;
- one bounded change;
- baseline;
- pass/fail criteria;
- rollback condition.
Do not propose multiple simultaneous changes.
```

## 4. Feedback translation

```text
Translate each reaction into an observable defect and actionable instruction:
- too generic;
- wrong tone;
- missed the point;
- inconsistent format;
- repeated omission;
- incorrect filtering.
Then identify the controlling lever for each.
```

## 5. Placement test

```text
Classify each proposed fix as:
- one-time prompt detail;
- instruction;
- governed knowledge;
- Skill or workflow;
- deterministic control; or
- human gate.
Explain why that is the narrowest durable home.
```

## 6. Promotion decision

```text
Evaluate whether this validated correction should remain local or be promoted:
[describe correction]
Assess recurrence, sharing, materiality, ownership, versioning, testing, rollback, conflicts, and review cadence.
```

## 7. Workflow instrumentation

```text
Observe this fictional recurring workflow:
[describe workflow]
Build an optimization backlog covering:
- repetition;
- recurring correction;
- operator variance;
- waiting and handoffs;
- rework;
- duplicated research or calculation;
- required controls that must remain.
```

## 8. Rule–reference–procedure audit

```text
Sort the workflow's reusable elements into:
- rules;
- references;
- procedures;
- deterministic logic;
- one-time details.
Recommend the correct configuration home for each and identify any misplaced content.
```

## 9. Metric selection

```text
For this workflow, identify:
- the primary optimization metric;
- three guardrail metrics;
- the baseline;
- the success threshold;
- the stop condition for diminishing returns.
Explain why general speed is or is not the correct target.
```

## 10. Guarded-pilot design

```text
Design a guarded pilot for this workflow optimization:
[describe change]
Include representative cases, users, edge cases, retained baseline, governance checks, approval owner, rollback trigger, and adoption decision.
```

## 11. Net-improvement review

```text
A change reduced drafting time by 25% but increased corrections and reviewer effort.
Evaluate net improvement across time, quality, consistency, cost, maintenance, risk, and downstream work.
Choose adopt, revise, revert, or gather more evidence.
```

## 12. Governance-preservation check

```text
Review this optimization proposal for weakened controls:
[describe proposal]
Check data classification, least privilege, source authority, Skill trust, human approval, fairness, disclosure, recourse, logging, and rollback.
```

## 13. Module 7 oral explanation

```text
Give a two-minute explanation of Module 7 suitable for an Associate certification interview.
Cover diagnosis, isolation, feedback translation, durable placement, workflow instrumentation, metrics, guarded rollout, and rollback.
```

## 14. Cross-module synthesis

```text
Explain how Module 7 depends on:
- Module 1 context and capability selection;
- Module 2 prompt structure and iteration;
- Module 3 evaluation;
- Module 4 workflow design;
- Module 5 configuration maintenance; and
- Module 6 governance.
Use one fictional workflow to connect all seven domains.
```

## 15. Transition to Module 8

```text
Create a readiness inventory for Course Summary & Next Steps.
For Modules 1–7, record:
- the core decision;
- one common failure;
- one reusable pattern;
- one escalation boundary;
- one topic needing further review.
```

## Completion statement

```text
I completed Module 7: Troubleshooting & Optimization.
I can diagnose underperformance, isolate causes, translate feedback, promote durable fixes, instrument recurring workflows, measure improvement, and preserve governance during optimization.
```

## Public-use rule

Use fictional, generic, synthetic, public, or authorized scenarios. Do not place private prompts, production logs, confidential workflow details, credentials, proprietary procedures, or reconstructed course questions in public materials.
